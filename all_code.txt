# Contributing to Programming Club Website
Welcome! Whether this is your first time using Git or you already code regularly, here is how we work together:

1. Read `documentation/development-docs/gitworkflow.md`, `commitconventions.md`, and `codingstandards.md`.
2. Pick an assigned task or GitHub Issue (or ask if you need a task).
3. Create a branch from `main` **(never push directly to `main`)**.
4. Make small, focused commits using our commit message format.
5. Open a Pull Request on GitHub when your task is ready for review.

If you get stuck with Git, CSS, or JS, ask in the club chat or open an issue. Don't stay stuck for hours alone.
==================== ./documentation/development-docs/coding_standards.md ====================
# Coding Standards

## General
- Use **2 spaces** for indentation (matching `.editorconfig`).
- Use clear, descriptive names in `kebab-case` for files and CSS classes, and `camelCase` for JS variables and functions.
- Keep changes scoped to your assigned files/task so you don't overwrite someone else's work.

## HTML
- Use semantic elements (`<header>`, `<nav>`, `<main>`, `<section>`, `<article>`, `<footer>`, `<button>`).
- Include `alt` text on images (`alt=""` only for purely decorative images).
- Avoid inline styles (`style="..."`) unless strictly dynamic.

## CSS
- Reuse shared CSS variables and layout classes before writing duplicate rules.
- Test layouts at both desktop and mobile widths (avoid fixed widths that cause horizontal overflow).

## JavaScript
- Write clean, readable ES6+ (`const` by default, `let` when reassigned, avoid `var`).
- Never put private keys, passwords, or email credentials in client-side code.
- Handle empty/missing data gracefully so the page doesn't break.
==================== ./documentation/development-docs/commit_conventions.md ====================
# Commit Conventions

Use the format:
`<type>: <short description in lowercase imperative/present tense>`

## Allowed Types
- `feat:` — new feature or section
- `fix:` — bug fix
- `style:` — CSS, formatting, or visual styling (not logic)
- `docs:` — documentation or copy/content updates
- `refactor:` — restructuring code without changing behavior
- `test:` — tests or verification helpers
- `chore:` — config, setup, or maintenance tasks

## Examples
- `feat: add member profile card layout`
- `fix: align mobile navbar toggle`
- `style: adjust project card spacing`
- `docs: add beginner git setup guide`
- `chore: add editorconfig and gitignore`

Avoid vague messages like `"update"`, `"stuff"`, or `"fix bug"`.
==================== ./documentation/development-docs/git_workflow.md ====================
# Git Workflow

## Golden Rule
**Never push directly to `main`.** All changes go through a branch and a Pull Request (PR).

## Step-by-Step Workflow
1. **Sync `main`:**
   in bash shell:
    git checkout main
    git pull origin main

2. **Create a branch for your task:**
    in bash shell:
     git checkout -b <type>/<short-description>

   Examples:
   - `git checkout -b feat/project-filter`
   - `git checkout -b style/faq-layout`
   - `git checkout -b docs/starter-resources`

3. **Stage and commit your work:**
    in bash shell:
     git add .
     git commit -m "feat: add category filter to project showcase"


4. **Push your branch:**
    in bash shell:
     git push -u origin <your-branch-name>


5. **Open a Pull Request:**
   - Go to GitHub, open a PR from your branch into `main`, fill out the PR template, and request a review.
   - After approval and merge, switch back to `main` and run `git pull origin main`.

## Branch Naming
- `feat/<name>` — new features or sections
- `fix/<name>` — bug fixes
- `style/<name>` — CSS/layout/visual updates
- `docs/<name>` — documentation or text content updates
- `refactor/<name>` — code cleanup without changing behavior

==================== ./documentation/project-docs/project_scope.md ====================
# Project Scope

## Objective
Build a clean, responsive, static website for the Programming Club using **HTML, CSS, and JavaScript**, deployed via **GitHub Pages**, that showcases member projects, introduces members, shares beginner learning resources, answers FAQs, and lets new students apply to join.

## In-Scope Sections
1. **Homepage (`index.html`)**
   - Club introduction, mission, meeting highlights, and quick navigation to all sections.
2. **Project Showcase**
   - Filterable list/grid of club projects—covering both **completed** and **in-progress** projects via status tags/filters.
   - Displays project name, description, status (`Completed` / `In Progress`), tech stack, contributors, screenshot/preview, live demo URL (when available), and GitHub repo URL.
3. **Member Directory**
   - Member cards with name, avatar (`assets/`), club role, favorite programming languages, short bio, and GitHub profile link.
   - Only publish member details/avatars with that member's permission.
4. **Starter Resources & Wiki**
   - Curated beginner guides, environment setup tips, language/Git tutorials, and club workflow references.
5. **Join Us Form**
   - Collects student name, contact info, programming experience, and interests/motivation.
   - Sends submissions to the club lead's email via an external form service or serverless endpoint (never hardcode email credentials in frontend JS).
6. **FAQ**
   - Answers common questions: experience needed, what to bring to meetings, languages covered, meeting schedule, joining projects, and how to join.

## Out of Scope (v1)
- Custom backend server or database hosted in this repo.
- User accounts, login/authentication, or admin dashboards.
- Heavy frontend frameworks or complex build pipelines.

- **Markup:** Semantic HTML5

- `src/scripts/` — JS modules (filtering, rendering cards, form handling, nav)

- `README.md` — Project overview & setup

- Agree on shared header/footer markup and CSS variables before building individual pages so styles stay consistent.
- Keep data (projects, members, FAQs) structured cleanly so UI rendering stays simple and maintainable.

==================== ./README.md ====================
# ProgrammingClub-Website
Official website for our Programming Club, built with **HTML, CSS, and JavaScript** and hosted on **GitHub Pages**.

## What's Included
- **Homepage / Index:** Club overview, purpose, activities, and highlights.
- **Project Showcase:** Filterable gallery of club projects (including active/in-progress projects alongside completed ones) with live demos, GitHub links, tags, and contributors.
- **Member Directory:** Member profile cards with role, favorite languages, short bio, GitHub link, and avatar.
- **Starter Resources & Wiki:** Setup guides, beginner tutorials, learning links, and club Git workflow notes.
- **Join Us:** Application form for prospective members (name, contact info, experience, interests/motivation) wired to a form/notification endpoint.
- **FAQ:** Answers to common questions about joining, meetings, languages, and projects.

## Getting Started Locally
   in bash shell:
   git clone https://github.com/YKC-ProgrammingClub/ProgrammingClub-Website.git
   cd ProgrammingClub-Website
